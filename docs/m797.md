# Kefico/Bosch M7.9.7

M7.9.7 support uses the existing GKFlasher CLI, GUI and checksum tool with gkbus. It requires Python 3.12 or newer and a K-Line interface.

## Operations

The examples use COM69; substitute your adapter's interface name.

```powershell
python gkflasher.py --protocol kline --interface COM69 --id
python gkflasher.py --protocol kline --interface COM69 --read-dtcs
python gkflasher.py --protocol kline --interface COM69 --read --output full.bin
python gkflasher.py --protocol kline --interface COM69 --read-calibration --output calibration.bin
python gkflasher.py --protocol kline --interface COM69 --read-program --output program.bin
python gkflasher.py --protocol kline --interface COM69 --flash-calibration full.bin
python gkflasher.py --protocol kline --interface COM69 --flash full.bin
python gkflasher.py --correct-checksum full.bin
```

Family detection runs before SIMK session or security commands. It requires positive identification responses; an absent ECU is reported as unknown. Modified calibration names are accepted. For recovery when application identification is unavailable, select the family manually or supply `--ecu-family m797`.

Bulk operations default to standard speed (`--desired-baudrate 0x64`, 57600 baud). Fast speed is `--desired-baudrate 0x82`, 108800 baud. Other selectors are rejected for M7.9.7 bulk operations.

In the GUI, use automatic detection or select “KEFICO 1.6 4mbit”. The existing read, flash, identification, trouble-code and checksum buttons route to the M7.9.7 backend. GUI flashing starts without an additional confirmation dialog. CLI flashing retains its confirmation prompt.

## BIN layout

| Region | ECU address, inclusive | BIN offset | Size |
| --- | --- | --- | --- |
| Boot | `0x800000–0x80FFFF` | `0x00000` | 64 KiB |
| Calibration | `0x810000–0x81FFFF` | `0x10000` | 64 KiB |
| Program | `0x820000–0x87FFFF` | `0x20000` | 384 KiB |

All reads save a 512 KiB BIN. Partial reads retain their original BIN offsets and pad unread areas with `0xFF`. Custom ranges use `--read --address-start ADDRESS --address-stop ADDRESS`; the stop address is exclusive.

Flashing requires a 512 KiB BIN. Before calibration flashing, the application reader fetches the ECU's 512-byte checksum table. The BIN must have matching descriptor ranges; the ECU's boot/program checksum entries are preserved while calibration checksums are recalculated. A failed table read or mismatched layout aborts before erase. Calibration flashing therefore requires a working application-side read path; recovery without that path requires a full flash. Full flashing requires boot and program data; padded calibration reads are rejected. The input file is not modified during flashing.

Program-only flashing, custom flash ranges, immobilizer operations, adaptive-value clearing, logging, RSW and MTOS are currently unsupported on M7.9.7.

Program-only flashing needs coordinated updates across regions: the program checksum entries are stored in the calibration region, and the boot-boundary integrity value is stored in the boot region. Writing only `0x820000–0x87FFFF` can therefore leave integrity fields incorrect even when the program bytes were transferred successfully.

Use a full flash for program changes so these fields are recalculated and written together. Program-only flashing is possible in principle, but a process that preserves calibration while updating the affected checksum and boot-integrity fields has not yet been implemented or validated.

## Checksums and programming completion

The checksum module owns the additive checksum algorithm, its 32 descriptor entries, complements and two boot-integrity fields. Both flashing and offline correction use it. A full image updates all fields; a padded calibration read updates only the calibration entries. The GUI preview lists only incorrect checksums and complements, grouped under friendly region names. Console output still reports all checked regions.

Offline correction previews changes and asks before saving, like SIMK. Saving checks that the original BIN still matches the preview, then replaces it atomically. Already correct images report `[+] Image checksums already correct.` in both frontends.

Compatible applications install a temporary RAM reset extension before programming and automatically reboot after all requested regions pass verification. The running dispatch pointers and code signatures determine compatibility, rather than a calibration-ID allowlist. Application identification at 10400 baud confirms recovery. Both CLI and GUI use the same backend. See [automatic reboot](m797-reboot.md) for compatibility checks, RAM layout and hardware evidence.

Reboot preparation uses small targeted reads: 284 bytes of dispatch tables and
the 126-byte reset handler. It does not read a complete program bank. RAM
validation and the separate 512-byte calibration checksum-table check remain.

Unrecognized code layouts, unsupported RAM parsers and blank-flash recovery retain the manual power-cycle process. Calibration flashing sends short-frame StopCommunication on that path; its acknowledgement confirms communication shutdown only.

## Implementation and verification

- `ecu_definitions.py`: memory layout, programming profiles, routine identifiers and RAM-layout profiles.
- `flasher/ecu.py`: shared family detection, identification and filename helpers; the M7.9.7 ECU layout adapter.
- `flasher/m797.py`: programming sessions, security, transfer planning and the three RAM-only read architectures.
- `flasher/m797_reboot.py`: fingerprinted RAM reset extension and application recovery confirmation.
- `flasher/checksum.py`: detection, correction, verification, reporting and offline saving.
- `gkflasher.py` and `gui.py`: argument/UI routing and progress presentation.

Normal commands use gkbus KWP commands, transport and channel APIs. Read and programming handoffs both set a 12-second response timeout in the backend, so CLI and GUI use the same timing. Two compatibility details remain local: gkbus currently exposes only a private keepalive-stop hook, and its K-Line transport does not support the short-frame StopCommunication exchange. That exchange uses the channel byte API at the active programming baud.

Backend operations accept the existing optional `log_callback` signal used by
the GUI. Without it, messages print to the CLI. M7.9.7 reuses the existing
helper in `flasher/rsw.py`; GUI logging does not replace `sys.stdout`.

Read batching preserves native/C166 16 KiB page clipping and LCR linear addressing. Temporary gate descriptors are restored and scratch tables are cleared before continuing; failed RAM cleanup aborts architecture discovery. Native reads use only the live descriptor plus `0xE6`; calibration-specific hints and known-word fallbacks are not used. Direct-RAM reads always use the generic probes in their established order, without calibration-specific profiles or exact-byte oracles. These structural probes establish that descriptors can be retargeted and return the expected length; they do not authenticate the flash contents. Firmware requiring a different native descriptor rule may fail to read. Automatic reboot retains its separate reset-handler fingerprint and ROM compatibility checks.

Run the hardware-free regression suite from the repository root:

```powershell
python -B -m unittest discover -s tests
```

The suite exercises the real gkbus transport through an in-memory K-Line channel, independent checksum fixtures, CLI routing and headless Qt workflows. Programming transcripts at both speeds are checked against captures from before the cleanup, with the live-table preflight tested separately. Regression coverage also checks that calibration-only writes preserve the live firmware checksums when the source BIN contains different program data, and that failed preflights never enter programming. These checks complement testing on the physical ECU; they cannot establish support for additional firmware variants.

OpenPort validation on GKE2I60 / QG6IS00E included a full 512 KiB backup,
checksum verification, matching reads at both speeds, GUI calibration reading,
and a calibration rewrite at 57600 baud. After a manual power cycle, all
65536 calibration bytes matched the backup. Subsequent testing with code-layout
discovery also completed a calibration rewrite at 108800 baud, rebooted
automatically and matched all 65536 readback bytes without a power cycle.
